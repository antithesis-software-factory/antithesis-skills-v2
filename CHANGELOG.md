# Version 0.1.0 (2026-11-01)

- **Breaking**: Workloads start the driver through a snapshot gate instead of a `singleton_driver_` test command. The driver is now its container's main process, and waits for a `snapshot-gate` container that Antithesis opens at the start of each timeline. To keep working on a workload built with the previous release, ask the agent to move it to the snapshot gate described in the workload module.
- **Breaking**: Every module now checks its dependencies before starting, and stops if one is missing: snouty, installed and authenticated (`snouty doctor` must pass), Docker or Podman with Docker Compose, and jq.
- **Breaking**: Triage takes a link to the run (`https://<tenant>.antithesis.com/run?run_id=...`) or a run ID, and no longer looks up a run from a triage report URL.
- New `properties` module, which adds properties to a workload: `define` turns a property the user describes into a check, and `import` adds properties from a catalog, spec, existing tests or past bugs, in batches the user picks. Each property is written down in `antithesis/properties/`, checked locally, broken on purpose to confirm it fails, then checked in a short run. The workload module no longer writes properties: its assertions mark the situations the workload should reach, to guide exploration ([#7](https://github.com/antithesishq/antithesis-plugin/pull/7)).
- Triage has three modes: `monitor` reports and triages failures while a run is in progress, `summary` summarizes a finished run and which failures are new, and `root-cause` investigates one failure, running commands at the failing moment or launching a targeted run when the logs aren't enough. Issue reports link the run and no longer carry a hidden fingerprint ([#7](https://github.com/antithesishq/antithesis-plugin/pull/7)).
- New `launch` module, which builds, validates and launches a workload with `snouty launch`. Runs are sized by compute budget instead of duration: short runs use `--max-compute-hours 12` and the final run `--max-compute-hours 24` on the standard tier, and the agent fixes a slow setup rather than raising the setup timeout ([#8](https://github.com/antithesishq/antithesis-plugin/pull/8)).
- Triage's instrumentation check uses the current properties, `Every instrumented module has symbols` instead of `Symbols were uploaded`, and also checks the path properties for Java, Python and .NET.
- The agent passes `--detail` to snouty instead of `--json`, except when it pipes the output into another program, which uses fewer tokens.
- In the multiverse debugger, the agent knows that `snouty runs exec` runs in the workload's containers, with only the tools installed there.
